Open source · secrets for agents

vaulted-agent

Give an AI coding agent real credentials without leaving them on disk. One small launcher resolves secrets from a vault into the agent’s process at start, runs it as a service account, and gives each harness only the secrets you named for it.

Claude Code Codex Grok 1Password · Bitwarden · pass bash · sudo
Install GitHub v0.1.0 release

What it does

You type vaulted-agent claude (or codex, or grok). The launcher becomes the agent account, scrubs the environment, injects only the secrets in that harness’s manifest, drops the vault token, and execs the agent. Secrets live in that process until it exits. 

you $ vaulted-agent claude
      │
      ▼
  /usr/local/bin/vaulted-agent
      ├─ sudo -u agent                 become the service account
      ├─ scrub environment             allowlist only
      ├─ op inject -i full.env.tpl     vault refs → values, in memory
      ├─ unset vault token             agent must not inherit the master key
      └─ exec claude …
             └─ secrets live here, until the process exits

What you get

  • One vault token on disk instead of a fleet of .env files
  • Central rotation — change the vault, every future launch picks it up
  • Diffable manifests: which agent can reach what
  • Nothing secret on the command line (ps stays clean)

Honest limits

  • Not “zero secrets on disk” — one service-account token remains
  • The agent can read its own environment (and so can anything as that user)
  • Manifests control blast radius, not full containment
  • Root on the host can still read everything

Install

Two supported paths. The one-liner only bootstraps from this host; the payload is always a tagged GitHub release, not floating main. Neither path writes your vault token for you.

One-liner 
curl -fsSL https://stephens.page/vaulted-agent/install.sh | bash
From GitHub (inspectable) 
git clone --branch v0.1.0 --depth 1 \
  https://github.com/JacobStephens2/vaulted-agent-launcher
cd vaulted-agent-launcher && sudo ./install.sh

Prefer not to pipe to bash? Download install.sh, read it, then bash install.sh. Pin with VAULTED_AGENT_VERSION=v0.1.0. Pass installer flags after bash -s -- (for example --user agent).

After install — vault token

One credential stays on disk (1Password example; other backends in the README):

Configure token 
printf 'OP_SERVICE_ACCOUNT_TOKEN=ops_...\n' | sudo tee /etc/vaulted-agent/op.env >/dev/null
sudo chown root:"$USER" /etc/vaulted-agent/op.env
sudo chmod 0640 /etc/vaulted-agent/op.env

sudo cp /etc/vaulted-agent/harnesses.d/claude.conf.example \
        /etc/vaulted-agent/harnesses.d/claude.conf
