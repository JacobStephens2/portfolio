From Machine Code to AI: the Same Hello World

August 1, 2026 · ~1,100 words · 10 live Run Program rungs · reading this as an AI agent? agents.md is for you

Every layer of the stack can print Hello, World!. The point of this page is not the string - it is what each layer hides, and that the buttons below really run allowlisted programs on this host (Linux x86_64), not a fake terminal.

I have been learning ARM64 Assembly on an Apple Silicon Mac in a private teach-skill workspace. Side by side with that practice, I wanted a public ladder: the same program from bytes to prompts, including C++ and C#, with a server that compiles and executes what you see. The Assembly here is x86_64 Linux GAS - the dialect this machine runs - not the macOS ARM64 sources from the private course. Naming that gap is part of the lesson.

What each level hides

Robert C. Martin has spent decades arguing that software history is a climb through successive languages and abstractions - and that craft still matters at every step. One framing of that arc shows up in his conversation with Kent Dodds. This ladder is abstraction order (how much of the machine you still name), not a pure release-year timeline. Lisp is older than C; Java sits between C and Go; history is messier than a blog figure.

  • Machine code - the bytes. The only language the CPU executes.
  • Assembly - human names for those encodings and registers.
  • C / C++ - portable systems languages; compilers choose instructions.
  • Rust / Go / C# - more runtime or safety machinery (ownership, GC, CLR/Mono).
  • Python / JavaScript - VMs and JITs; you almost never name registers.
  • AI engineering - intent in natural language. Still bottoms out below.

Fig. 1 · Ten rungs, real execution

Each Run Program posts to /blog/from-machine-code-to-ai-the-same-hello-world/api/run/{language}. The body carries only the language key. Source is fixed under programs/ on the server. There is no arbitrary remote code execution - only an allowlist of Hello Worlds.

Fig. 2 · How the runner stays boring
  • Allowlisted language ids only (machine, assembly, c, …).
  • No user-supplied source, argv, or env from the browser.
  • Build once into cache/, then execute with a hard timeout.
  • systemd: loopback bind, NoNewPrivileges, PrivateTmp, memory cap.
  • Per-IP rate limit on the API.
If a demo needs to be interesting, the security story should stay dull. Arbitrary-code paste boxes do not belong on a public blog host.

What you should notice when you mash Run

  • stdout converges - almost every rung prints the same line. The interesting delta is wall time, toolchains, and the machine-code dump.
  • C is a hinge - short source, native binary, still close enough that compiler output looks like Assembly.
  • Managed runtimes show up as process shape - Mono for C#, Node for JS, CPython for Python - not as different letters on the screen.
  • AI is an interface, not an escape hatch - the AI rung returns a deterministic stand-in for an LLM so the page stays free and reproducible. A real model would still emit text or code that bottoms out in one of the lower rungs.

What's still open

The private ARM64 teach path and this public x86_64 ladder are deliberately different ISAs - good for honesty, awkward for copy-paste between Mac and server. A dual-target Assembly pair (Apple Silicon vs Linux amd64) would make the platform gap visceral. The AI rung is also intentionally not a live model call; wiring a budgeted, logged, content-filtered model would be a different post about product risk, not Hello World.
